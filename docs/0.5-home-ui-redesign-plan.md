# CleanDesk 首页 UI 重构方案

## 1. 当前首页问题分析

CleanDesk 的首页最初围绕“单个监控文件夹”设计。进入 0.5 多监控文件夹后，首页继续沿用原结构，导致信息密度和层级开始失衡。

主要问题：

- 监控文件夹、运行状态、操作、规则、最近活动都以独立卡片呈现，卡片数量偏多。
- “运行状态”和“操作”是同一任务链路，却被拆成两张卡片，右侧区域容易出现空白和割裂感。
- 多监控文件夹增加了“当前文件夹”和“所有文件夹监听”的概念，但当前页面没有形成清晰的控制中心。
- 规则区承担了主要配置工作，但在现有双栏结构中空间不够稳定，看起来像后续叠加的功能区。
- 最近活动已经承担用户反馈、撤销、详细日志入口，但视觉上仍像附属日志面板。
- 用户需要同时理解“我管理哪些文件夹”“现在是否运行”“下一步该点什么”“规则如何生效”“刚刚发生了什么”，当前结构没有把这些问题按优先级组织。

重构目标不是增加功能，而是重新安排现有入口，让首页更像成熟桌面软件的工作台。

## 2. 新首页信息架构

推荐采用“四区工作台”结构：

1. 顶部左侧：监控文件夹
2. 顶部右侧：控制中心
3. 中部全宽：自动整理规则
4. 底部全宽：最近活动

信息优先级：

- 第一眼：当前管理哪些文件夹、自动整理是否运行。
- 第二眼：下一步可以做什么。
- 第三眼：规则如何整理文件。
- 第四眼：最近整理结果和可撤销操作。

建议将“运行状态”和“操作”合并为“控制中心”卡片。状态和动作属于同一上下文，合并后能减少卡片割裂，也能避免右侧出现两张小卡片互相抢空间。

## 3. 宽屏布局方案

宽屏断点建议继续使用当前 `1100px` 左右逻辑，不必新增复杂响应式系统。

布局建议：

```text
Header

┌──────────────────────────────┬──────────────────────────────┐
│ 监控文件夹                    │ 控制中心                      │
│ 文件夹数量 / 列表 / 当前选择   │ 状态 / 说明 / 三个主操作按钮   │
│ 添加 / 移除                   │                              │
└──────────────────────────────┴──────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 自动整理规则                                                 │
│ 智能整理建议 / 新建整理规则                                  │
│ 规则列表                                                     │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 最近活动                                                     │
│ 撤销上一次整理 / 查看详细日志                                │
│ 活动列表                                                     │
└─────────────────────────────────────────────────────────────┘
```

宽屏比例建议：

- 顶部两列平分或近似平分。
- 监控文件夹卡片和控制中心卡片高度以内容自然高度为主。
- 自动整理规则作为主要工作区，获得中部主要空间。
- 最近活动保持全宽，承担反馈和历史信息。

## 4. 窄屏布局方案

窄屏继续使用单栏纵向布局，不强行双栏。

顺序建议：

1. 监控文件夹
2. 控制中心
3. 自动整理规则
4. 最近活动

窄屏原则：

- 页面整体继续放在 `QScrollArea` 中，允许纵向滚动。
- 每张卡片按内容自然高度显示，规则区和活动区可设置合理最小高度。
- 控制中心按钮保持纵向排列，避免横向挤压。
- 文件夹路径、规则目标、活动详情都必须允许换行，不出现横向滚动条。

## 5. 每个区域具体显示内容

### 监控文件夹

显示：

- 标题：`监控文件夹（N）`
- 副标题：
  - 停止时：`选择当前要整理的文件夹；开始自动整理后会监听所有文件夹。`
  - 运行中：`自动整理运行中。停止后可管理监控文件夹。`
- 文件夹列表：
  - 文件夹名称
  - 完整路径
  - 当前选中状态
- 操作：
  - `+ 添加文件夹`
  - `移除当前文件夹`

行为保持不变：

- 点击文件夹只切换当前文件夹。
- 运行中允许切换当前文件夹。
- 运行中禁用添加和移除。
- 不允许重复路径和父子嵌套路径。

### 控制中心

由原“运行状态”和“操作”合并。

显示：

- 标题：`控制中心`
- 状态块：
  - `已停止`
  - `运行中`
- 状态说明：
  - 停止时：`添加或选择文件夹后，可以整理当前文件夹。`
  - 运行中：`正在监听 N 个文件夹`
- 操作按钮：
  - `开始自动整理`
  - `停止自动整理`
  - `整理当前文件夹`

建议视觉层级：

- 状态块在顶部，按钮在状态下方。
- `开始自动整理` 仍是唯一 Primary Button。
- `停止自动整理` 仍是 Danger Button。
- `整理当前文件夹` 仍是 Secondary Button。
- 没有监控文件夹时按钮可点击并给出引导提示，保持 0.5.1 的体验修复方向。

### 自动整理规则

显示：

- 标题：`自动整理规则`
- 副标题：`上方规则会优先匹配。`
- 右上操作：
  - `智能整理建议`
  - `+ 新建整理规则`
- 规则列表：
  - 排序入口
  - 规则名称
  - 匹配条件
  - 目标文件夹
  - 编辑 / 删除

规则区应成为首页的主要工作区。建议全宽展示，给规则名称、匹配条件和目标路径更多呼吸空间。

### 最近活动

显示：

- 标题：`最近活动`
- 副标题：`这里会显示最近的整理结果。`
- 右上操作：
  - `撤销上一次整理`
  - `查看详细日志`
- 活动列表：
  - 已整理 / 未整理 / 整理失败 / 已撤销
  - 来源文件夹
  - 移动目标
  - 命中规则
  - 打开所在位置

## 6. 需要合并的卡片

建议合并：

- `运行状态` + `操作` -> `控制中心`

不建议合并：

- `监控文件夹` 不应并入控制中心。它是对象管理区域，不是即时操作区。
- `自动整理规则` 不应并入监控文件夹。规则是全局共享配置，和当前文件夹是不同概念。
- `最近活动` 不应并入控制中心。活动是结果反馈和历史记录，应该保持独立全宽区域。

## 7. 功能入口保留位置

| 功能入口 | 新位置 |
| --- | --- |
| 添加监控文件夹 | 监控文件夹卡片 |
| 移除当前文件夹 | 监控文件夹卡片 |
| 切换当前文件夹 | 监控文件夹列表 |
| 开始自动整理 | 控制中心 |
| 停止自动整理 | 控制中心 |
| 整理当前文件夹 | 控制中心 |
| 智能整理建议 | 自动整理规则卡片右上 |
| 新建整理规则 | 自动整理规则卡片右上 |
| 编辑规则 | 每条规则项右侧 |
| 删除规则 | 每条规则项右侧 |
| 规则优先级排序 | 每条规则项左侧 |
| 撤销上一次整理 | 最近活动卡片右上 |
| 查看详细日志 | 最近活动卡片右上 |
| 打开所在位置 | 已整理活动项内 |

## 8. 规则区为未来拖拽排序预留空间

本轮不实现拖拽排序，但规则项结构建议为未来拖拽预留左侧操作区。

当前方案：

```text
┌──────┬───────────────────────────────┬──────────────┐
│ ↑ ↓  │ 规则名称 / 条件 / 目标文件夹   │ 编辑 删除     │
└──────┴───────────────────────────────┴──────────────┘
```

未来拖拽方案：

```text
┌──────┬───────────────────────────────┬──────────────┐
│ ⋮⋮   │ 规则名称 / 条件 / 目标文件夹   │ 编辑 删除     │
└──────┴───────────────────────────────┴──────────────┘
```

建议：

- 左侧保留固定宽度 `28px ~ 36px` 的排序区域。
- 现阶段显示 `↑ / ↓`。
- 未来可替换为拖拽把手，或同时保留键盘可访问的上下移动按钮。
- 不要把排序入口放到右侧，避免和编辑 / 删除混在一起。

规则拖拽排序建议放在首页 UI 重构之后。先稳定新布局和规则项结构，再引入拖拽会更安全。

## 9. 最近活动空状态设计

空状态应轻量，不要占用过高空间。

建议文案：

```text
还没有整理记录
点击“整理当前文件夹”，CleanDesk 会在这里显示整理结果。
```

显示位置：

- 活动区域中央偏上。
- 主提示稍明显。
- 副提示使用浅灰色次级文字。

交互：

- 有活动后自动隐藏空状态。
- 撤销按钮仍然显示但禁用，并保持明显的禁用视觉。
- 查看详细日志入口仍然保留。

## 10. 预计需要修改的文件

预计主要修改：

- `ui.py`

可能需要很小范围确认但不应主动修改：

- `service.py`：仅当 UI 缺少只读状态数据时，才考虑补充只读方法。

不应修改：

- `watcher.py`
- `engine.py`
- `rules.py`
- `storage.py`
- `version.py`
- `README.md`
- `releases/`

## 11. 不应该被修改的业务逻辑

UI 重构不应改变以下逻辑：

- 多监控文件夹配置模型；
- 添加 / 移除 / 切换当前文件夹的规则；
- Start 扫描并监听所有有效监控文件夹；
- Stop 停止所有监听；
- 整理当前文件夹只扫描当前 active folder；
- 智能整理建议只分析当前 active folder；
- 全局规则优先级；
- 新建 / 编辑 / 删除规则；
- 相对目标路径和绝对目标路径解析；
- 重名冲突处理；
- 最近活动生成逻辑；
- 打开所在位置；
- 撤销上一次整理；
- 撤销期间 watcher ignore 保护；
- 详细日志记录。

## 12. 建议实施步骤

建议拆成 3 步，避免一次性大改。

### 步骤 1：合并右侧控制区

修改：

- 将 `_status_card()` 和 `_actions_card()` 合并为 `_control_center_card()`。
- 保留原按钮对象和状态标签对象，减少信号绑定变化。
- 宽屏顶部右侧使用控制中心。
- 窄屏顺序调整为监控文件夹 -> 控制中心 -> 规则 -> 最近活动。

验证：

- Start / Stop 状态切换；
- 监听数量显示；
- 空文件夹按钮提示；
- 1600x900 / 850x700 布局。

### 步骤 2：规则区全宽主工作区

修改：

- 将规则卡从左列中移到中部全宽。
- 规则列表项保留左侧排序区。
- 确保规则列表无横向滚动。
- 保持智能整理建议和新建规则入口在右上。

验证：

- 规则排序；
- 编辑 / 删除；
- 新建规则；
- 智能整理建议；
- 窄屏规则项不重叠。

### 步骤 3：最近活动收口

修改：

- 最近活动保持底部全宽。
- 优化空状态高度和文案。
- 检查撤销按钮、详细日志、打开所在位置在新布局下的可用性。

验证：

- 空状态；
- 有活动后隐藏空状态；
- 已整理活动显示来源和打开所在位置；
- 撤销按钮状态；
- 详细日志弹窗。

## 13. UI 重构后的验收标准

布局验收：

- `1600x900`：顶部双卡自然铺开，规则区全宽，最近活动全宽。
- `1200x800`：无重叠、无横向滚动。
- `850x700`：单栏顺序正确，页面可纵向滚动。
- 控制中心不出现大块无意义空白。
- 规则区可读性提升，至少能稳定显示多条规则。
- 最近活动空状态不显得空荡。

功能入口验收：

- 添加监控文件夹可用；
- 移除当前文件夹可用；
- 切换当前文件夹可用；
- 开始自动整理可用；
- 停止自动整理可用；
- 整理当前文件夹可用；
- 智能整理建议可用；
- 新建整理规则可用；
- 编辑 / 删除规则可用；
- ↑ / ↓ 排序可用；
- 撤销上一次整理可用；
- 查看详细日志可用；
- 打开所在位置可用。

业务回归验收：

- Start 仍扫描并监听所有有效监控文件夹；
- Scan Now 仍只整理当前文件夹；
- 智能整理建议仍只分析当前文件夹；
- 规则仍全局共享；
- 相对路径仍落在各自来源文件夹；
- 绝对路径不被拼接；
- 撤销与 watcher ignore 保护不受影响；
- 最近活动不显示开发日志。

发布边界：

- 首页 UI 重构不应改版本号；
- 不应修改 release 归档；
- 不应打包；
- 不应创建 tag。
