# CleanDesk 0.6.0-beta 设置中心方案

## 1. 设置中心目标

CleanDesk 的定位是“本地自动化文件管家”。0.6.0-beta 的设置中心用于集中管理少量、明确且会影响日常整理体验的偏好，同时为未来后台运行能力预留稳定入口。

第一版应满足：

- 普通用户无需理解内部队列、watcher 或配置字段；
- 默认行为保守，不因升级自动开始移动文件；
- 危险行为不作为默认选项；
- 设置保存在本地 `config.json`，不上传文件或配置；
- 不改变多监控文件夹、全局规则、忽略规则和撤销的现有产品模型。

## 2. 0.6.0-beta 包含的设置

### 2.1 常规

#### 启动 CleanDesk 时自动开始整理

- 控件：开关；
- 默认：关闭；
- 建议在 0.6.0-beta 实现；
- 开启后，仅在至少存在一个有效监控文件夹时自动启动；
- 若部分文件夹不可用，沿用现有逻辑跳过并提示，其余文件夹继续运行；
- 首次欢迎提示未确认时，不应在提示出现前自动整理；
- 文案说明：“打开 CleanDesk 后自动开始监听已添加的文件夹。”

这是后台文件管家方向的基础能力，但默认开启会造成意外移动风险，因此必须由用户主动选择。

#### 开始整理时扫描已有文件

- 控件：开关；
- 默认：开启，以保持当前 Start 行为；
- 建议在 0.6.0-beta 实现；
- 语义：无论用户手动点击“开始自动整理”，还是由应用启动触发自动整理，都决定是否先扫描顶层已有文件；
- 关闭后只监听之后新增的文件；“整理当前文件夹”仍是独立手动操作，不受影响；
- 文案说明：“开始自动整理时，先处理文件夹中已经存在的文件。”

使用“开始整理时”而不是含糊的“启动时”，可避免用户误以为每次打开软件都会无条件扫描。

#### 关闭窗口时

0.6.0-beta 只显示当前可用选项：

- 直接退出（默认且唯一可选）。

“最小化到系统托盘”可以作为禁用项显示“即将支持”，但更推荐本版完全不展示，待托盘能力真实实现后再加入，避免出现无法生效的设置。

### 2.2 整理

#### 手动整理遇到同名文件

- 控件：下拉选择或单选组；
- 选项：
  - 每次询问（默认）；
  - 自动保留两个；
  - 自动跳过。

适用于“整理当前文件夹”和 Start 的启动前扫描。选择“每次询问”继续沿用现有中文冲突对话框。

#### 自动监听遇到同名文件

- 控件：下拉选择或单选组；
- 选项：
  - 自动保留两个（默认，保持现有行为）；
  - 自动跳过。

自动监听不提供“每次询问”，避免后台任务被阻塞。手动与自动场景分开设置，用户更容易理解，也与当前代码中的 `manual/start_scan` 和 `auto` 模式一致。

#### 暂不提供“自动替换”

自动替换会不可逆地删除目标位置已有文件，风险明显高于 CleanDesk 当前的安全定位。即使增加二次确认，也不适合作为“默认策略”。0.6.0-beta 不提供该选项；未来若引入回收站、安全备份或可恢复替换机制后再评估。

### 2.3 最近活动

#### 最近活动保留数量

- 控件：下拉选择；
- 选项：50、100、200；
- 默认：50，保持当前行为；
- 建议实现；
- 保存后立即生效：新上限更小时立即裁剪最旧记录，新上限更大时只影响后续记录。

当前最近活动仅是本次运行中的内存列表，设置控制 UI 内存数量，不代表跨重启保存活动。详细技术日志仍由 `logs/app.log` 独立保留，不受该值影响。

#### 清空最近活动

- 控件：次级按钮“清空最近活动”；
- 点击后显示确认框；
- 确认后立即清空首页活动列表；
- 不删除 `logs/app.log`；
- 不清空撤销栈，避免把“清空展示”误变成“失去撤销能力”；
- 这是即时动作，不随设置窗口的“取消”回滚。

### 2.4 关于

只读展示：

- CleanDesk；
- 当前版本（从 `version.py` 读取，不在 UI 中写死）；
- 本地自动化文件管家；
- 开发者：Zmx；
- “所有整理均在本机完成，不上传文件。”；
- “当前版本为 Beta，建议先使用测试文件夹。”

现有“帮助 → 关于 CleanDesk”可以保留。设置中心“关于”与其内容应复用同一份文本生成函数，避免版本信息不一致。

## 3. 暂不包含的设置

0.6.0-beta 不实现：

- 系统托盘与最小化到托盘；
- Windows 开机启动；
- 系统通知；
- 云同步、账号、AI/API；
- 多用户或远程同步；
- 每个监控文件夹独立规则；
- 自动替换同名文件；
- 日志文件保留周期、日志级别等开发者选项。

未来可在现有设置窗口中增加“后台运行”分组，但不应提前放置无效开关。

## 4. UI 结构方案

### 4.1 入口

在菜单栏新增顶级菜单“CleanDesk”或“应用”，其中放置“设置”；考虑当前菜单栏只有“帮助”，最小改动方案是：

- 新增“设置”菜单；
- 菜单项：“打开设置”；
- “帮助”继续保留“关于 CleanDesk”。

不建议把设置按钮塞进首页卡片，首页应继续聚焦文件夹、控制、规则和活动。

### 4.2 窗口形式

推荐独立模态 `QDialog`，采用单页纵向滚动的分组卡片，而不是“左侧分类 + 右侧内容”。原因：

- 第一版只有四组，分类导航增加了不必要的操作层级；
- 单页更适合 PySide6 当前卡片风格；
- 约 620～700px 宽，最小高度约 600px；
- 内容超出时只出现纵向滚动，不出现横向滚动；
- 关于区放在最底部，视觉权重最低。

建议结构：

```text
设置
├── 常规
│   ├── 启动 CleanDesk 时自动开始整理 [开关]
│   └── 开始整理时扫描已有文件       [开关]
├── 整理
│   ├── 手动整理遇到同名文件          [下拉]
│   └── 自动监听遇到同名文件          [下拉]
├── 最近活动
│   ├── 最多保留                      [50/100/200]
│   └── 清空最近活动                  [按钮]
├── 关于
│   └── 名称、版本、开发者、本地隐私说明
└──                         [取消] [保存]
```

### 4.3 保存方式

推荐“保存 / 取消”，而不是每次改变都即时写盘：

- 打开窗口时复制当前 settings；
- 用户修改表单不会立即影响运行；
- 点击“保存”时整体校验并一次写入；
- 点击“取消”放弃未保存修改；
- “清空最近活动”是明确的即时动作，执行前单独确认。

这种方式更符合桌面设置窗口预期，也减少连续写 `config.json`。

## 5. 配置字段设计

基于当前顶层字段 `monitored_folders`、`active_folder_id`、`monitored_folder`、`welcome_shown` 和 `rules`，新增独立的 `settings` 对象：

```json
{
  "monitored_folders": [],
  "active_folder_id": "",
  "monitored_folder": "",
  "welcome_shown": false,
  "rules": [],
  "settings": {
    "auto_start_organizing": false,
    "scan_existing_on_start": true,
    "manual_duplicate_policy": "ask",
    "auto_duplicate_policy": "keep_both",
    "recent_activity_limit": 50
  }
}
```

字段与允许值：

| 字段 | 类型 | 默认值 | 允许值/语义 |
|---|---:|---|---|
| `auto_start_organizing` | bool | `false` | 应用启动并完成首次提示后自动调用开始整理 |
| `scan_existing_on_start` | bool | `true` | 开始自动整理时是否先扫描已有顶层文件 |
| `manual_duplicate_policy` | string | `ask` | `ask` / `keep_both` / `skip` |
| `auto_duplicate_policy` | string | `keep_both` | `keep_both` / `skip` |
| `recent_activity_limit` | int | `50` | 仅接受 `50` / `100` / `200` |

不在配置中提前加入 `close_behavior`、`minimize_to_tray`、`launch_at_login` 或 `notifications_enabled`。未实现字段容易形成错误承诺，未来功能落地时再迁移。

## 6. 默认值建议

- 自动开始整理：关闭，防止升级后意外移动文件；
- 开始整理时扫描已有文件：开启，保持当前 Start 语义；
- 手动重名策略：每次询问，给用户明确控制；
- 自动监听重名策略：保留两个，避免阻塞和覆盖；
- 最近活动数量：50，保持当前性能和界面体验；
- 自动替换：不提供。

## 7. 与现有功能的关系

### Start / Stop

- `auto_start_organizing` 复用现有 service `start()`，不创建另一套启动流程；
- `scan_existing_on_start` 仅控制 `start()` 内的启动前扫描步骤，不能影响 watcher 启动；
- Stop 行为不变；
- 自动启动失败时应保持 Stopped，并给出用户可读提示。

### 重名处理

- worker 已区分 `manual`、`start_scan` 和 `auto` 模式；
- 手动策略用于 `manual` 和 `start_scan`；
- 自动策略用于 `auto`；
- “ask”仍通过现有 UI signal bridge 在主线程显示对话框；
- `keep_both` 与 `skip` 复用现有安全处理，不改变重命名算法。

### 最近活动与详细日志

- `recent_activity_limit` 替换 UI 中写死的 50；
- 该设置只控制首页活动列表，不修改 `logs/app.log`；
- 清空最近活动不影响详细日志、undo stack 或正在运行的 watcher；
- 本版不新增最近活动磁盘持久化。

### 多文件夹、规则与忽略规则

- settings 为全局设置；
- 所有监控文件夹使用同一套重名策略；
- 不改变规则优先级、忽略优先、智能建议和目标路径解析；
- 自动开始时仍扫描/监听所有有效监控文件夹。

## 8. 旧 config 兼容方案

迁移放在 `storage.py` 的读取边界，与现有文件夹配置规范化一致：

1. `_default_config()` 加入完整默认 settings；
2. `load()` 对顶层数据做现有合并后，再单独调用 `_normalize_settings(config)`；
3. 旧配置缺少 settings 时补全默认值；
4. settings 只包含部分字段时逐项补默认值，不能用浅层 `config.update()` 覆盖掉嵌套默认值；
5. bool 字段做严格归一化，枚举值不合法时回退默认值；
6. 最近活动数量不在允许集合时回退 50；
7. 保留 settings 中未知字段，便于未来版本向前兼容；
8. 不修改、删除 `monitored_folders`、`active_folder_id`、兼容字段 `monitored_folder`、`welcome_shown`、`rules` 或用户自定义字段。

读取时可在内存中补齐；沿用当前 service 初始化时 `_persist_config()` 的行为写回规范化结构。测试必须使用临时配置，不直接改用户真实 `config.json`。

## 9. 生效时机

| 设置 | 生效时机 |
|---|---|
| 自动开始整理 | 下次启动 CleanDesk |
| 开始整理时扫描已有文件 | 保存后的下一次 Start（包括下次自动启动） |
| 手动重名策略 | 保存后的下一次手动冲突 |
| 自动监听重名策略 | 保存后的下一次自动冲突，可在运行中生效 |
| 最近活动保留数量 | 保存后立即生效 |
| 清空最近活动 | 用户确认后立即执行 |

设置保存不应自动 Start、Stop 或重启 watcher。用户修改自动启动设置时，只影响下一次应用启动。

## 10. 实施拆分建议

### 阶段 A：配置结构与 service 接口

实施状态：已完成。

修改：`storage.py`、`service.py`，增加针对临时配置的测试。

- 实现 settings 默认值与安全归一化；
- service 暴露 `get_settings()` / `update_settings()`；
- 将 Start 的已有文件扫描开关、冲突策略和活动数量接入既有流程；
- 保持 UI 暂时不变也可运行。
- `auto_start_organizing` 已具备配置字段与 service 接口，实际自动启动编排留到阶段 C。

重点回归：旧 config、Start、手动/自动重名、活动列表上限。

### 阶段 B：设置窗口

实施状态：已完成。

主要修改：`ui.py`。

- 新增菜单入口和 `SettingsDialog`；
- 实现四个分组、保存/取消和字段说明；
- 实现清空活动确认；
- About 内容复用版本与开发者常量。

已实现：设置菜单入口、`SettingsDialog`、常规设置、整理设置、最近活动设置、关于信息、保存/取消和清空最近活动。

重点回归：主界面响应式布局不变、设置窗口可重复打开、取消不保存。

### 阶段 C：自动启动与收口测试

修改：`main.py`、`ui.py` 或 service 启动编排的最小位置，以及文档。

- 在欢迎提示处理完成后，根据配置安排一次自动 Start；
- 避免窗口构造期间重复启动；
- 处理无文件夹、无有效文件夹和部分文件夹不可用；
- 更新 README、版本和发布测试记录。

## 11. 测试清单

### 配置兼容

- 无 settings 的旧 config 自动补齐，文件夹和规则不丢失；
- settings 只有部分字段时补齐其余字段；
- 非法 bool、枚举和活动数量回退默认值；
- 中文路径、绝对目标路径和 ignore action 不受影响；
- 空 config 和损坏 config 使用安全默认值启动。

### 常规设置

- 自动开始默认关闭；
- 开启后，下次启动在欢迎提示完成后开始监听全部有效文件夹；
- 无监控文件夹时不崩溃并提示；
- 扫描开关开启时 Start 先扫描已有文件；
- 扫描开关关闭时 Start 只监听新文件；
- “整理当前文件夹”不受扫描开关影响；
- 保存设置不会改变当前 Running/Stopped 状态。

### 重名策略

- 手动 `ask` 显示现有中文冲突对话框；
- 手动 `keep_both` 自动生成 `_1` 安全名称；
- 手动 `skip` 保留源文件并显示中文活动；
- 自动监听 `keep_both` 不弹框且继续监听；
- 自动监听 `skip` 不弹框、不移动并显示中文活动；
- 设置中不存在“自动替换”；
- 撤销时的冲突交互保持现有安全逻辑，不被整理设置意外覆盖。

### 最近活动

- 50、100、200 分别限制列表数量；
- 从大值改为小值后立即裁剪最旧记录；
- 清空前有确认，取消不清空；
- 清空后首页恢复空状态；
- 清空不删除详细日志、不清除撤销批次；
- 新活动仍可继续出现。

### 设置窗口与关于

- 菜单入口可打开设置窗口；
- 保存写入 config，取消不写入；
- 窗口较矮时可纵向滚动，无横向滚动；
- About 显示正确版本、Zmx 和本地隐私说明；
- 反复打开/关闭不会重复绑定信号或创建后台任务。

### 核心回归

- 多文件夹添加、选择、移除；
- Start / Stop 和整理当前文件夹；
- move 与 ignore 规则优先级；
- 规则拖拽排序；
- 智能整理建议；
- 最近活动来源显示与打开所在位置；
- 撤销及监听状态下撤销保护；
- 1600×900、1200×800、850×700；
- `python -m compileall .`；
- PyInstaller onedir 冷启动。
