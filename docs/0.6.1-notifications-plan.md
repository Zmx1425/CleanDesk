# CleanDesk 0.6.1-beta 后台通知

## 1. 设计原则

- 通知只补充重要结果，不替代首页最近活动和详细日志。
- 不为单个移动成功、单个忽略结果或普通文件事件逐条通知。
- 通知失败不得阻塞扫描、监听、撤销或程序退出。
- 通知内容只使用用户可读中文，不显示异常对象、堆栈或完整路径。

## 2. 配置

`settings.notifications_enabled` 控制后台通知，默认值为 `true`。旧配置缺少该字段或字段不是布尔值时回退为开启。设置保存后立即影响后续通知，取消不会保存。

关闭通知不会停止整理，也不会影响最近活动、详细日志和撤销记录。

## 3. 第一版通知场景

- Windows 登录静默启动且自动整理成功：每次程序启动最多通知一次监听文件夹数量。
- 自动开始整理失败：每次程序启动最多通知一次，并使用安全中文原因。
- 启动时监控文件夹不可用：同一次 Start 汇总通知，只显示文件夹名称。
- watcher 因重名策略自动跳过：在 7 秒窗口内汇总为一条通知。
- 手动“整理当前文件夹”完成：整个批次只生成一条移动、忽略、跳过汇总；没有可整理结果时显示对应提示。

主窗口正在前台时，可抑制普通完成通知；自动启动失败和文件夹不可用仍可通知。

## 4. 明确不通知

- 单个文件移动成功或被忽略；
- watcher 收到文件事件；
- 普通 Start / Stop 点击；
- 保存设置、打开窗口或智能整理建议；
- 普通无异常日志。

## 5. 聚合与去重

- 自动启动成功、失败分别使用一次性内存标记。
- 不可用文件夹由一次 Start 的校验结果统一汇总。
- 自动重名跳过由单次 `QTimer` 聚合，退出时停止定时器并清空待发内容。
- 所有通知统一通过托盘通知管理器调用 `QSystemTrayIcon.showMessage()`。

## 6. 与最近活动的关系

最近活动继续记录完整的用户操作结果。通知关闭或系统托盘不可用时，最近活动仍正常追加；清空最近活动也不会更改通知设置。

## 7. 后续范围

后续版本可单独评估更细的通知类别开关和免打扰时段。本版本不提供通知历史、声音设置、Windows 通知中心管理或逐文件通知。
